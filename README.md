# Прогноз оттока клиентов сервиса доставки кофе

Модель бинарной классификации, которая оценивает вероятность того, что клиент сервиса доставки кофе Happy Beans Coffee уйдёт в следующем месяце. Бизнес может заранее предложить таким клиентам удерживающие акции и не тратить бюджет на тех, кто и так остаётся.

Итоговый проект спринта «Машинное обучение» в Яндекс Практикуме.

## Задача

- **Тип задачи:** бинарная классификация (`churn`: 1 — клиент может уйти, 0 — лояльный).
- **Метрика:** PR AUC. Уходящих клиентов всего 6%, поэтому важно качество именно на редком классе.
- **Модель:** логистическая регрессия, чтобы бизнес видел, какие признаки связаны с оттоком.
- **Требования:** воспроизводимость (`random_state`), обработка пропусков, кросс-валидация, сохранение всего пайплайна предобработки вместе с моделью.

## Данные

`datasets/coffee_churn_dataset.csv` — 10 450 клиентов и 27 признаков за последние 4 недели: частота и сумма заказов, средний чек, скидки и промокоды, вкусовые предпочтения, подписка, активность в приложении и его сбои, оценки заказов, сезон, устройство и регион.

Особенности: дисбаланс классов (6% уходящих), пропуски почти во всех признаках (1–9.5%) и выбросы, в том числе невозможные значения: отрицательные траты, до 224 заходов в приложение в неделю.

## Что сделано

1. **Подготовка среды:** версии библиотек фиксируются в `requirements.txt` прямо из ноутбука.
2. **Исследовательский анализ:** пропуски, категории, выбросы, проверка нормальности (тест Шапиро-Уилка) и корреляции Спирмена. Тестовая выборка откладывается до анализа связей с целевой переменной, все выводы о признаках сделаны только по train.
3. **Предобработка в пайплайне:** `ColumnTransformer` с отдельными ветками для числовых, категориальных и бинарных признаков. Собственный трансформер `OutlierClipper` обрезает выбросы по квантилям, границы обучаются в `fit`, то есть отдельно в каждом фолде кросс-валидации.
4. **Базовые модели:** `DummyClassifier` и логистическая регрессия на стратифицированной кросс-валидации (5 фолдов).
5. **Новые признаки и отбор:** проверено 5 новых признаков, оставлены `crashes_squared` (квадрат числа сбоев) и `app_opens_sqrt` (корень из числа заходов). Удалены дублирующие и не связанные с оттоком признаки.
6. **Подбор гиперпараметров:** `GridSearchCV` по `C`, `penalty` и `class_weight`, всего 20 конфигураций.
7. **Финальная оценка** на отложенной тестовой выборке.
8. **Сохранение модели:** весь пайплайн сохранён через `joblib` и проверен после загрузки.

## Результаты

| Модель | PR AUC (CV) |
|---|---|
| DummyClassifier | 0.060 |
| Логистическая регрессия, все признаки | 0.668 |
| + новые признаки | 0.719 |
| + отбор признаков | 0.725 |
| + подбор гиперпараметров | 0.727 |

**На тестовой выборке:** PR AUC **0.746**, precision 0.77, recall 0.59 (порог 0.5). Из 126 уходящих клиентов модель нашла 74. Из 96 клиентов, которых она отметила, 22 на самом деле остаются.

**Итоговая модель:** `LogisticRegression(C=100, penalty='l2', solver='liblinear')`, 11 числовых признаков, `subscription_status` и 3 бинарных признака.

## Что связано с оттоком

- **Сбои приложения** — самый сильный сигнал. При 0–1 сбое в месяц уходит меньше 1% клиентов, при 3 сбоях 41%, при 4 и больше почти все.
- **Заходы в приложение:** с ростом активности отток растёт с 2.5% до 11%, связь нелинейная.
- **Подписка pro:** отток 11.1%, почти вдвое выше среднего.
- Вкусовые предпочтения, сезон, тип телефона и регион с оттоком почти не связаны.

Модель находит связи, а не причины ухода. Исправление сбоев и пересмотр условий подписки pro — гипотезы для проверки, например A/B-тестом.

## Как запустить

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt jupyter
```

Ноутбук рассчитан на платформу Практикума, где данные лежат по пути `/datasets/coffee_churn_dataset.csv`. Для локального запуска поменяй путь в ячейке загрузки на `datasets/coffee_churn_dataset.csv`.

Для загрузки модели в другом месте нужно объявить класс `OutlierClipper` и функцию `add_features` из ноутбука:

```python
import joblib

model = joblib.load('models/churn_model.joblib')
churn_probability = model.predict_proba(new_clients)[:, 1]
```
